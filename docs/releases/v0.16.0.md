Choose your machines - and two of any of them. Patches that change with the song, a Juno that morphs, and closing that asks before it saves.

## Downloads

- **MzDebirth-0.16.0-win64-Setup.exe** - Windows: the installer. The app, a Start menu entry,
  an uninstaller, and the Mz950's fifteen sample disks. Per-user installs need no admin rights.
- **MzDebirth-0.16.0-win64.zip** - Windows: the same, to run without installing. Keep the
  `disks` folder beside `MzDebirth.exe`.
- **MzDebirth-0.16.0-macOS-beta.zip** - macOS (beta): the app and the Mz950's disks, with an
  install script.
- **mzdebirth_0.16.0_amd64.deb** - Linux (beta), for Ubuntu 22.04 and later, Debian, Mint and
  the like: installs MzDebirth in the applications menu.
- **MzDebirth-0.16.0-linux-x86_64-beta.tar.gz** - Linux (beta), any 64-bit x86 distribution:
  unpack and run, nothing installed.
- **mzdebirth_0.16.0_arm64.deb** - Raspberry Pi 5 (beta), on 64-bit Raspberry Pi OS Bookworm or
  later: installs MzDebirth in the menu, under Sound & Video.
- **MzDebirth-0.16.0-linux-arm64-beta.tar.gz** - the same for any 64-bit ARM distribution:
  unpack and run, nothing installed.

**Windows:** Windows 10 or 11, 64-bit. The app is not code-signed, so Windows may warn about
an unknown publisher: choose **More info**, then **Run anyway**.

**macOS:** Apple Silicon and Intel Macs, macOS 11 or later. The download isn't signed by
Apple, which takes a paid developer account, so macOS won't open it with a double-click.
Unzip it, then in Terminal type `bash ` (with a space), drag `install.sh` from the unzipped
folder into the window, and press Return. It puts the app in Applications and the disks in
`~/Library/Application Support/MzDebirth`, and clears the quarantine flag. `READ ME FIRST.txt`
in the zip explains how to install by hand instead.

**Linux:** with the .deb,

    sudo apt install ./mzdebirth_0.16.0_amd64.deb

then open MzDebirth from the applications menu, or run `mzdebirth`; `apt` fetches what it
needs, and `sudo apt remove mzdebirth` takes it away again. With the .tar.gz, unpack it
anywhere and run `./MzDebirth` in it, keeping the `disks` folder beside it; `READ ME
FIRST.txt` in it lists the few libraries a minimal system might lack. It plays through ALSA,
which PipeWire and PulseAudio both provide.

**Raspberry Pi 5:** install the arm64 .deb the same way,

    sudo apt install ./mzdebirth_0.16.0_arm64.deb

and choose the "default" or "pipewire" output under Options. A Pi is much slower than a
desktop PC, so if the sound crackles, raise the buffer size there. It's built natively on
GitHub's ARM machines, passes the same checks as the others, and has been played on a Pi 5.
A Pi 4 on 64-bit Raspberry Pi OS may run it too, if more slowly; a 32-bit system won't.

## What's new

- **Choose your machines.** **+ MACHINE**, beside the RACK and ARRANGE tabs, adds a machine to
  the rack, and the **×** at the top right of a machine's panel takes it out again, its
  patterns and knobs kept for when it comes back. Most racks don't want all seven: a machine
  left out has no panel, no track and no mixer channel, and isn't played at all, which helps on
  a Raspberry Pi.
- **Two of any machine.** Pick a machine that's already in and you get a second of it: two
  303s, two 909s, two Juno-106s. A second is a whole machine with its own patterns, knobs,
  patches and channel, and sits under its first in the rack and the Arrange window.
- **Patches that change with the song.** In the Arrange window, right-click a part on the
  Mz950, the Mz7 or the Mz106 and pick its **Patch**: a programme, a voice or a patch of the
  machine's own. The part plays on it from its first note, and its name shows on the part. A
  part left on *The panel's own* plays whatever the panel has picked, so a song sounds the
  same whether you start it from the top or halfway through.
- **The Mz106 morphs.** **MORPH TO** picks a second patch and **MORPH** moves from one to the
  other. The sliders move step by step and the switches flip half way. Automate MORPH for slow
  sweeps from one sound to another.
- **Closing asks before it saves.** With changes that haven't been saved, closing asks whether
  to save them: to the rack's file, or where you say the first time. Don't save, and they're
  gone; the app opens next time with the rack as it was last saved. Nothing changed, and it
  just closes.

Racks saved before open as they were: the first of each machine in the rack, no seconds.
Everything else is as in [0.15.0](https://github.com/simozzer/MzDebirth/releases/tag/v0.15.0).
